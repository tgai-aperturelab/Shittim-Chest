# 成员任务入口

以下是适合拆成 Issue 的首批工作。认领前先查现有 Issue 和代码，确认还未被其他人完成；每项都可以独立交付一个 PR。没有编程经验也可以从第 1 项开始。

| 工作 | 难度与入口 | 交付与验收 |
| --- | --- | --- |
| 新成员安装体验记录 | 入门；`CONTRIBUTING.md` | 在一台没有生产配置的 Windows 或 Linux 机器上从克隆开始跑通离线检查，修正文档中的实际缺项；记录操作系统、Python 版本和脱敏检查结果 |
| 配置字段说明 | 入门至中等；`src/shittim_core/app/config.py`、三个配置样例 | 补充字段分组、默认值、相对路径含义和互斥条件；示例能通过现有配置测试，不包含真实账号与令牌 |
| 跨平台视觉探针 | 中等；`tools/vision_probe.py` | 该工具目前指定 Windows Arial 字体路径；改为可配置字体或明确的跨平台回退，并在无该字体时给出可理解的结果；离线验证无需调用收费视觉模型 |
| 独立 Linux 隔离验证 | 进阶；`tests/integration/test_bubblewrap.py` | 为具备 namespace 权限的测试环境提供可复现的运行说明，验证任务目录、Python runtime 和网络隔离；环境不支持时明确报告，不自动放宽隔离 |

更深入的开发可以围绕引用与附件、多人协作、上下文整理、执行工具和恢复机制展开。先描述一个具体使用过程、现有不足和预期结果，再讨论修改范围；不要先把新业务写死进 Agent 内核。

缺陷报告使用 Issue 的“问题反馈”模板，附最小复现和期望行为；功能或任务使用“开发任务”模板。先提交 Draft PR 也可以，维护者会帮助把范围收敛为可审阅的修改。
