# StateStore contract (W2)

All methods are synchronous, short SQLite transactions (`timeout=0`), with no network/model operations. Construction is explicit: `StateStore(path: str | Path)`; imports create no resources. The connection is owned by its creating thread. `close()` is idempotent. Database busy/constraint errors surface as `StateConflict`.

## Intake, context and control

- `ingest(event: InputEvent) -> tuple[str, bool]`: stable input ID, duplicate flag; uniqueness uses `event.key`.
- `get_input(input_id: str) -> InputEvent`.
- `list_unbound_inputs() -> list[tuple[str, InputEvent]]`: stored inputs not associated with any context, including clarification candidates; in durable intake order. Does not guess association or run anything.
- `resolve_input(address: ConversationAddress, message_id: str) -> dict[str, Any] | None`: input_id/context_id only for exactly one associated input at the exact bot/address/message key; ambiguous multiple contexts return None.
- `create_context(context_id: str, event: InputEvent, access: AccessContext, controllers: Iterable[str] = ()) -> None`: creates context only; caller separately attaches the previously ingested input. Owner is `event.author_id`; default address is `event.address`.
- `attach_input(context_id: str, input_id: str) -> int`: stable context sequence; attaching the same input again returns the original sequence.
- `get_context(context_id: str) -> dict[str, Any]`: `context_id`, `owner_id`, `controllers` (list), `address` (ConversationAddress), `access` (AccessContext), `control_state` (`active/paused/closed`), `control_epoch`, `input_seq`, `history_version`, `policy_version`.
- `list_contexts(address: ConversationAddress | None = None) -> list[dict[str, Any]]`: exact address filter when supplied.
- `list_events(context_id: str, after_seq: int = 0) -> list[dict[str, Any]]`: unified sequence order. Input rows contain `seq`, `event_id=input_id`, `input_id`, `event` (InputEvent), `kind="input"`, `audience=original address.key`, `source_ids=[input_id]`. Result rows contain `seq`, `event_id="result:"+result_id`, `kind="material_result"`, `input_id=original source_input_id`, `event=None`, `payload`, `source_ids=[source_input_id]`, `audience`.
- `append_result_event(context_id: str, source_input_id: str, result_id: str, payload: dict[str, Any], audience: str) -> int`: source input must already belong to the context. Atomically saves the derived event and advances the same input_seq. Repeating the same globally unique result_id/content/scope returns its original sequence; conflicting reuse raises StateConflict. Paused/closed contexts record only and do not reopen. The trusted caller supplies a verified disclosure scope; persisting the string does not grant permission.
- Cross-address input/results may be associated but are not automatically disclosure-authorized; ContextBuilder must filter by audience/explicit access. A derived event is never represented as a new human InputEvent. Recovery uses the unified input_seq so unconsumed result events remain eligible only in active contexts.
- `set_controllers(context_id: str, owner_id: str, controllers: Iterable[str]) -> None`: owner only; advances control epoch to invalidate prior authority.
- `claim_run(context_id: str, run_id: str) -> int`: returns current control epoch; requires active context and no running run. Carries forward the last consumed sequence; claiming alone does not consume newly accepted input. build_view/consume_inputs advances it.
- `get_run(run_id: str) -> dict[str, Any]`: `run_id`, `context_id`, `status`, `control_epoch`, `input_seq`, `text`, `outcome`.
- `control(context_id: str, actor_id: str, action: str) -> ControlReceipt`: only owner or explicit controllers; stop/close invalidates current epoch; resume advances epoch and marks active. Denied controls do not mutate.
- `assert_current(run_id: str, epoch: int, input_seq: int | None = None) -> None`: raises `RunHalted` for invalid epoch/state/run; `StaleView` when supplied input sequence differs from current sequence.
- `revoke_running_authority() -> list[str]`: synchronously fences all currently running run IDs in this StateStore instance, then advances their context epochs in one transaction; returns affected context IDs. Does not change active/paused/closed states, terminate runs, cancel effects, or write outcomes. The caller invokes it once before asynchronous shutdown cleanup and finalizes unfinished runs as interrupted. If the epoch write fails, StateConflict surfaces while this instance's assert_current still rejects fenced run IDs. This local safety fence is not inherited by a fresh StateStore; durable recovery remains necessary after restart. A failed transaction is not evidence of persisted revocation.
- `consume_inputs(run_id: str, input_seq: int) -> None`: call after accepting the current ContextView; validates current sequence and updates the run's consumed sequence used for final delivery. begin_effect also records its validated sequence.

## History and effects

- `append_history(run_id: str, message: dict[str, Any]) -> None`: ordered persistent history; tool messages delegate to upsert.
- `history(context_id: str) -> list[dict[str, Any]]`: decoded model messages in append order.
- `history_records(context_id: str) -> list[dict[str, Any]]`: preserved raw records including archived history, with message/audience/source_ids/run_id. Use history() for the current compacted view.
- `upsert_tool_result(run_id: str, call_id: str, result_message: dict[str, Any]) -> None`: one tool-result row per run/call. An unknown result can later become an actual result. An unknown update never replaces a known terminal result. This API does not change effect status.
- `begin_effect(run_id: str, call_id: str, tool: str, args: dict[str, Any], resource_keys: Iterable[str], input_seq: int) -> str`: records attempting and logical resource claims atomically after current-run/input checks. Duplicate run/call or related attempting/unknown resource raises StateConflict. Caller must already persist the assistant tool-call message.
- `get_effect(effect_id: str) -> dict[str, Any]`: `effect_id`, `run_id`, `call_id`, `tool`, `args`, `resource_keys`, `status`, `result` (ToolResult or None).
- `list_effects(context_id: str | None = None) -> list[dict[str, Any]]`: same structure as get_effect, filtered through run ownership; use durable effects rather than inferred model history during compaction.
- `finish_effect(effect_id: str, result: ToolResult) -> None`: attempting/unknown may transition to actual result; only actual executing task or explicit reconciliation invokes this method. A known terminal result cannot be downgraded to unknown; conflicting terminal results raise StateConflict. Terminal states release logical claims, unknown keeps them. Never re-executes a handler.
- `finish_effect_with_history(effect_id: str, result: ToolResult) -> None`: normal tool completion path; effect result, logical resource release and one matching tool-history row commit in the same transaction. A history write error rolls back all three. A late unknown preserves already known effect/history truth. finish_effect remains the low-level recovery/testing interface.

## Outbox and inquiry

- `prepare_notice(input_id: str, text: str, access: AccessContext, context_id: str | None = None) -> str`: atomically records a router notice at the real input address. access.actor_id must equal the actual input author and access.audience must match its address.key. Without context, creates a stable independent context with `kind="router_notice"`; otherwise requires the same address and an owner/explicit-controller author. Associates only this input, creates a terminal yielded run with outcome.kind=router_notice and consumed_input_ids=[input_id], then creates one purpose=control Delivery. Does not change the original task's control_state, live run or model history. Same input/text/destination is idempotent; a changed context for the same identity is a conflict. Unknown/acknowledged notices are never re-created for retransmission.
- `get_context` and `list_contexts` additionally expose `kind="work" | "router_notice"`. Independent notice contexts are not implicit work targets. Normal claim/recovery consumption ignores router-notice runs; they cannot make unrelated input look consumed. The notice's receipt can be resolved with resolve_sent like any other delivery.
- Input rows from `list_events` include `handled_by_notice` (bool). The builder may omit these deterministic routing inputs from model history; source records remain intact. Recovery ignores handled notice inputs while still considering earlier unconsumed human inputs and all unconsumed derived results. A notice delivery tolerates newer input sequence alone, but still checks its recorded control epoch and current disclosure address.

- `prepare_delivery(run_id: str, intent: OutboundIntent, input_seq: int) -> str`: stable id for the same run/intent; records prepared. One intent is one send item: reject mixed text+artifact or more than one artifact, so caller must fan out multi-item sends.
- `prepare_delivery_items(run_id, intents: Iterable[OutboundIntent], input_seq) -> tuple[str, ...]`: atomically records an ordered batch and every item. Formatting/splitting is the caller's responsibility. Same plan is idempotent; distinct repeated text fragments retain distinct position IDs.
- `list_delivery_items(delivery_id) -> list[dict[str, Any]]`: complete batch in ordinal order, including already acknowledged/failed/unknown entries. Legacy single records return a one-item list. get_delivery also exposes batch_id and ordinal for batch entries. The head item's status is not the aggregate batch status.
- `finish_run_items(run_id, status, text="", final_intents=(), *, reason="", unresolved_effects=()) -> tuple[str, ...]`: terminal outcome and the entire ordered response plan commit atomically; a bad later item rolls back earlier items and outcome. Stable terminal plan cannot change on retry. Items may use purpose=message for a bounded error response without changing the actual failed/yielded outcome.
- `finish_run` retains its single-item return API and also accepts keyword-only reason/unresolved_effects. Outcome JSON persists reason plus the sorted union of reported and durable attempting/unknown effect IDs. Terminal idempotency checks reason and unresolved effects as well as status/text; reconciliation updates effect records, not a contradictory re-finalization of the old run.
- `get_delivery(delivery_id: str) -> dict[str, Any]`: `delivery_id`, `run_id`, `context_id`, `intent` (OutboundIntent), `status`, `input_seq`, `control_epoch`, `receipt` (ProtocolReceipt or None).
- `list_deliveries(status: str | None = None) -> list[dict[str, Any]]`.
- `claim_delivery(delivery_id: str) -> dict[str, Any] | None`: atomically prepared->attempting after epoch/input/disclosure check. Invalid unsent item becomes superseded and returns None. A repeated claim returns None. Default context address is allowed; other addresses require exact `ConversationAddress.key` in allowed_recipients. Control-purpose messages may send while paused if epoch is current.
- Batch claims additionally require every preceding item to be acknowledged in the same state transaction. Failed/unknown/attempting predecessors block the tail, including across restart or when a caller starts from a tail ID. Acknowledged prefix items are never re-claimed. The block does not fabricate a result for unattempted tail items.
- `finish_delivery(delivery_id: str, receipt: ProtocolReceipt) -> None`: attempting/unknown -> receipt; acknowledged mapping keyed by address+message_id. A late unknown cannot erase acknowledged.
- Delivery's `add_receipt_listener(async_callback)` runs only after an actual ACK is durably saved. Callback exceptions are recorded by class in listener_failures, do not downgrade the ACK, and never trigger a resend. Each new batch item ACK has its own listener notification; replaying an acknowledged batch invokes no listeners again.
- `finish_run(run_id: str, status: str, text: str = "", final_intent: OutboundIntent | None = None) -> str | None`: commits run outcome and stable final delivery together. Same final outcome is idempotent. Does not mark tool effects completed.
- `resolve_sent(address: ConversationAddress, message_id: str) -> dict[str, Any] | None`: `context_id`, `inquiry_id`, `delivery_id`, `purpose`.
- `create_inquiry(run_id: str, recipient_id: str, address: ConversationAddress, question: str, input_seq: int, inquiry_id: str | None = None) -> tuple[str, str]`: inquiry and prepared delivery atomic; returns inquiry_id, delivery_id. Optional explicit ID supports idempotent tool calls.
- `get_inquiry(inquiry_id: str) -> dict[str, Any]`: `inquiry_id`, `context_id`, `run_id`, `recipient_id`, `address`, `question`, `status`, `delivery_id`, `answer_input_id`.
- `answer_inquiry(inquiry_id: str, input_id: str) -> tuple[str, int]`: verifies actual input author/address, acknowledged inquiry delivery and live inquiry; associates input and answers atomically. Returns context_id, input sequence. Paused context stores answer without opening execution. Repeating same answer is idempotent.
- `list_open_inquiries(context_id: str | None = None) -> list[dict[str, Any]]`.
- `cancel_inquiry(run_id: str, inquiry_id: str, input_seq: int) -> dict[str, Any]`: current run/epoch/input, same context, only open can change (already cancelled is idempotent). Prepared delivery becomes superseded; attempted, unknown or acknowledged delivery stays truthful.
- `replace_inquiry(run_id: str, inquiry_id: str, recipient_id: str, address: ConversationAddress, question: str, input_seq: int, replacement_id: str | None = None) -> tuple[str, str]`: atomically supersedes old open question/unsent delivery and creates the new question/delivery. Same explicit replacement ID and payload is idempotent; differing reuse is a conflict. Neither operation retracts sent messages or clears unknown effect locks.
- `record_late_answer(inquiry_id: str, input_id: str) -> dict[str, Any]`: only cancelled/superseded inquiry and matching real address/recipient. Records immutable audit association without original context seq/pending/history changes. Returns inquiry_id/input_id/context_id/inquiry_status/event/source_ids/audience; same pair is idempotent.
- `list_late_answers(inquiry_id: str | None = None, *, context_id: str | None = None) -> list[dict[str, Any]]`: audit records with the same structure. These are not new facts for the original model view and do not wake that task.

## Recovery and CAS

- `register_artifact(artifact_id: str, context_id: str, owner_id: str, audience: str, path: str, sha256: str, version: int = 1, source_ref: str | None = None) -> None`: stores metadata only; no file read/download. Version must advance monotonically; same exact record is idempotent. Does not grant access based on path.
- `get_artifact(artifact_id: str) -> dict[str, Any]`: artifact_id, context_id, owner_id, audience, path, sha256, version, source_ref. MaterialStore enforces current AccessContext before reading bytes. Old versions remain available via `get_artifact(artifact_id, version=...)`.

- `recover() -> dict[str, list[str]]`: interrupts running runs, advances their context epochs, changes attempting effects/deliveries to unknown, retains logical unknown resource claims; returns `interrupted_runs`, `unknown_effects`, `unknown_deliveries`, `active_contexts`, `closed_tool_calls`. Active contexts are only those with unconsumed input; paused/closed are never returned. Missing persisted tool-result tail rows are closed with actual persisted results, unknown for uncertain effects, or not_executed when no effect acquired dispatch rights. Recovery never executes or sends.
- Recovery additionally returns `interrupted_contexts`: active work contexts whose latest non-router-notice run is interrupted, including runs that already consumed all source inputs. This preserves saved-history continuation without broadening active_contexts. A newer completed/yielded/failed/cancelled run prevents an older interruption from reactivating that context; later router notices do not replace the last work run. Reporting a candidate is not dispatch authorization: the Coordinator must still enforce current policy and defer unknown/attempting effects or deliveries. No historical tool call is replayed by StateStore.
- `compare_and_swap_history(context_id: str, expected_version: int, messages: list[dict[str, Any]], *, expected_epoch: int | None = None, expected_input_seq: int | None = None, expected_policy_version: int | None = None) -> bool`: replaces model view history only when versions match; old history is archived, not deleted. Does not remove source inputs/effects; rejects while effects are attempting/unknown. Caller validates complete tool groups before invoking.

Stop does not kill an in-flight task. Loop may upsert unknown to close model history and return; actual task later calls finish_effect and upsert_tool_result with its real result. These APIs never turn already succeeded effects back into unknown.
